# AI Accessibility Audit

<TableOfContents headings={['Quick start', 'Setup', 'Run the audit', 'Example prompts', 'Report and limitations']} />

Run iterative **WCAG 2.2 AA** audits on your locally running app with an AI agent, **Playwright MCP**, and **axe-core**.
PDS components are tested at component level — your **application integration** (pages, routing, custom content) still
needs its own audit. Agent scans complement manual keyboard, screen reader, and High Contrast Mode testing.

<Notification heading="Prerequisite" headingTag="h3" state="warning">
  Complete [AI Agent Context](/must-know/accessibility/ai-agent-context/) first — `AGENTS.md` and platform coding rules
  for accessible code generation.
</Notification>

## Quick start

1. **Install the audit skill** — download the bundle → move `accessibility-audit/` to
   `.agents/skills/accessibility-audit/` (includes report template at `references/report-template.md`)
2. **Configure Playwright MCP** in your agent (see [Setup](#setup))
3. **Start your dev server** — note the `localhost` URL
4. **Run** `/accessibility-audit` or paste an [example prompt](#example-prompts)
5. **Finish** — agent fills `references/report-template.md` and saves **`accessibility-audit-report-{date}.md`** in your
   repo root

| ------------------- | ------------------------------------------------------------------------------------------------ |
| **Audit skill**     | Extract ZIP → `.agents/skills/accessibility-audit/` (`SKILL.md`, `references/`, report template) |
| **Report template** | Stays in skill: `.agents/skills/accessibility-audit/references/report-template.md` — do not move |

| **Plan artifact**   | Agent writes `.accessibility-audit-plan.json` at **repository root** (resumable audit state)     |
| **Coding rules**    | [AI Agent Context](/must-know/accessibility/ai-agent-context/) — `AGENTS.md` + platform rules    |

```json
  }
}
```

## Run the audit

Invoke `/accessibility-audit` or use a prompt. The skill guides the agent through:

| Step | What                                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------------------ |
| 0    | **Scope** — URLs, viewports (~320px / ~768px), themes, exclusions                                                        |
| 1    | **Static PDS scan** — aria-on-host, icon-only controls, missing focus styles                                             |
| 2a–d | **Automated checks** — axe-core, focus visibility, page structure, keyboard/modals                                       |
| 3–4  | **Triage + plan** — severity grouping; `.accessibility-audit-plan.json`                                                  |
| 5–6  | **Fix loop** — propose fixes, re-scan until clean                                                                        |
| 7–8  | **Manual pass + report** — `references/manual-checklist.md` → filled `accessibility-audit-report-{date}.md` at repo root |

Detailed scripts, fix guides, and WCAG coverage matrix live in the skill's `references/` folder.

## Example prompts

### Full audit

```text
Conduct a WCAG 2.2 AA accessibility audit on http://localhost:3000/.

Scope: URLs /, /checkout; viewports 320px and 768px; light and dark themes.
Use the accessibility audit skill. Run axe, triage, fix, re-scan. Save the report as accessibility-audit-report-{date}.md in the repo root.
```

### Re-scan after fixes

```text
Re-run axe on http://localhost:3000/checkout at 320px and 768px.
Compare to the previous audit. List only remaining violations.
```

## Report and limitations

The **report template** is part of the skill (`references/report-template.md`). The agent reads it during step 8 and
writes a completed report to **`accessibility-audit-report-{date}.md`** in your repository root. Keep
`.accessibility-audit-plan.json` there too for resumable audits.

Include scope, violations, fix status, manual test results, and the Jira-ready summary block.

**Agent audits cannot:** certify screen reader compatibility, replace legal accessibility statements, or catch
everything axe misses (focus visibility, structure — covered by skill steps 2b–2c). Always complete the manual checklist
before sign-off.

**Standard:** [WCAG 2.2 Level AA](https://w3.org/WAI/standards-guidelines/wcag). Porsche guidance:
[Accessibility of digital products at Porsche](https://ux.porsche.com/d/6VNB3CeLHcJz/accessibility#/accessibility/introduction).
