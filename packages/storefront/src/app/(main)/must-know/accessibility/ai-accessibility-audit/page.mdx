# AI Accessibility Audit

<TableOfContents headings={['Install', 'Run an audit', 'Limitations']} />

Run guided **WCAG 2.2 AA** audits on your locally running application with
[**web-accessibility-audit**](https://github.com/porsche-design-system/skills/tree/main/packages/web-accessibility-audit).
PDS components are tested at component level; pages, routing, and custom content still need their own audit.

For generation-time guardrails, see [**AI Agent Context**](/must-know/accessibility/ai-agent-context/).

## Install

Install [APM](https://microsoft.github.io/apm/quickstart/) if needed:

- macOS: `brew install apm`
- Linux / macOS without Homebrew: `curl -sSL https://aka.ms/apm-unix | sh`
- Windows: `irm https://aka.ms/apm-windows | iex`)

Then from the product repository root install the **package** and pass `--target` for the agent harnesses that should
receive the files. Comma-separate several values to target different harnesses.

This package deploys to `copilot`, `cursor`, `claude`, `gemini`, `codex`, `windsurf`, and `agent-skills`. A repo with no
harness markers and no `targets:` list in `apm.yml` will fail `apm install` until you set `--target`.

One harness:

```bash
apm install porsche-design-system/skills/packages/web-accessibility-audit#web-accessibility-audit--v0.4.0 --target cursor
```

Several harnesses (comma-separated):

```bash
apm install porsche-design-system/skills/packages/web-accessibility-audit#web-accessibility-audit--v0.4.0 --target cursor,claude,copilot
```

To move version, re-run `apm install` with the new package tag. To remove it, run `apm uninstall` and `apm install`
again.

## Run an audit

Start the app locally, then invoke a prompt. Copilot binds them as chat commands (`/a11y-audit`). Cursor and Claude
expose the same names as commands; if the `a11y-audit` agent is not bound, the prompt still runs that workflow with the
installed skills.

| Prompt                         | Use when                                   |
| ------------------------------ | ------------------------------------------ |
| `a11y-audit`                   | Full single-page audit (axe + code review) |
| `a11y-quick-check`             | Fast axe-only triage                       |
| `a11y-audit-multi-page`        | Compare several pages                      |
| `a11y-lead`                    | Review specific UI files                   |
| `a11y-component-library-audit` | Audit a component directory                |
| `a11y-fix`                     | Apply fixes from a previous report         |

The report lands in `.a11y/runs/<timestamp>/` (`ACCESSIBILITY-AUDIT.md` and script-generated `findings.json`). Score,
grade, and finding identity come from a pinned rule catalog, so two runs of the same prompt should match on those fields
when the page and scanners are unchanged. Details:
[package README](https://github.com/porsche-design-system/skills/tree/main/packages/web-accessibility-audit).

**Full audit:**

```text
Run a WCAG 2.2 AA accessibility audit on http://localhost:3000/.

Scope: URLs /, /checkout; viewports 320px and 768px; light and dark themes.
Use a11y-audit and save results in the default .a11y/runs directory.
```

**Re-scan after fixes:**

```text
Re-run the audit on http://localhost:3000/checkout at 320px and 768px.
Compare against the previous run and list only remaining violations.
```

## Limitations

Behavioral scans need compatible browser tooling; if they cannot run, the audit lists those checks under **Not
Verified** instead of guessing. Agent audits do not certify screen-reader compatibility, replace a legal accessibility
statement, or catch everything automated tools miss. Complete keyboard and assistive-technology testing before sign-off.

**Standard:** [WCAG 2.2 Level AA](https://w3.org/WAI/standards-guidelines/wcag). Porsche guidance:
[Accessibility of digital products at Porsche](https://ux.porsche.com/d/6VNB3CeLHcJz/accessibility#/accessibility/introduction).
