Install generation-time **WCAG 2.2 AA** and **EN 301 549** (web clauses) context for GitHub Copilot, Claude Code, and
Cursor with the
[**web-accessibility-codegen** package](https://github.com/porsche-design-system/skills/tree/main/packages/web-accessibility-codegen)
from the [**porsche-design-system/skills**](https://github.com/porsche-design-system/skills) repository.

Installation uses [**APM (Agent Package Manager)**](https://microsoft.github.io/apm/). APM installs and updates the
always-on instruction and the on-demand `accessible-frontend` skill in your target repository.

This package does **not** duplicate Porsche Design System component APIs. When `@porsche-design-system/components-*` is
installed, the skill loads the version-exact `pds-knowledge-*` skill that ships in that npm package. Prefer PDS
components when that skill loads; otherwise use semantic HTML.

APM deploys Copilot, Cursor, and Claude files. It does not overwrite an existing project `AGENTS.md`. Do not paste a
stub `AGENTS.md`.

## Install the codegen package

Install the package from `porsche-design-system/skills` with APM.

### 1) Install APM

#### macOS / Linux

```bash
curl -sSL https://aka.ms/apm-unix | sh
```

#### Windows

```powershell
irm https://aka.ms/apm-windows | iex
```

### 2) Install the codegen package in your product repository

Run from your product repository root:

```bash
apm install porsche-design-system/skills/packages/web-accessibility-codegen#v0.1.0
```

This installs the package and deploys supported primitives for your detected targets (for example Copilot, Claude,
Cursor).

### 3) Optional: manage via `apm.yml`

For team workflows, declare the dependency in your repository's `apm.yml` and run `apm install`:

```bash
apm install
```

```yaml
dependencies:
  apm:
    - git: https://github.com/porsche-design-system/skills.git
      path: packages/web-accessibility-codegen
      ref: v0.1.0
```

You can list `web-accessibility-audit` next to it in the same `apm.yml`.

### Common APM commands

| Command                                                                              | Purpose                                                    |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| `apm install`                                                                        | Install from `apm.yml` / refresh deployed primitives       |
| `apm install porsche-design-system/skills/packages/web-accessibility-codegen#v0.1.0` | Add the package with an explicit version                   |
| `apm update`                                                                         | Update dependencies according to declared refs/constraints |
| `apm uninstall porsche-design-system/skills/packages/web-accessibility-codegen`      | Remove the package dependency                              |
| `apm prune`                                                                          | Remove no-longer-required cached packages                  |

For first-time APM setup and authentication troubleshooting, see the official
[APM Quickstart](https://microsoft.github.io/apm/quickstart/).

## How it works

After install, generate or edit frontend code as usual. The instruction applies to frontend globs (`html`, `css`,
`scss`, `js`, `ts`, `tsx`, `jsx`, `vue`, `mdx`). The agent should load `accessible-frontend` before writing markup.

Typical triggers: pages, forms, modals, tables, navigation, buttons, links, toasts.

### Always-on instruction (`frontend-a11y`)

Non-negotiable WCAG 2.2 AA / EN 301 549 rules: keyboard, focus, High Contrast Mode, zoom, forms, landmarks. It points at
`accessible-frontend` for the rest.

### On-demand skill (`accessible-frontend`)

Topic files for structure, keyboard and focus, forms, live regions, visual/HCM/zoom, and EN 301 549. Then, if PDS is in
the project, the skill resolves `pds-knowledge-js` / `-react` / `-vue` / `-angular`.

### Porsche Design System component skill

`pds-knowledge-*` ships inside `@porsche-design-system/components-*` (for example
`node_modules/@porsche-design-system/components-react/skills/pds-knowledge-react/`). For each PDS component, load both
`references/components/<tag>/<tag>.md` and `references/components/<tag>/accessibility.md` when that file exists.

Cursor and Copilot do not scan `node_modules` for skills. The APM skill still reads those files from disk. Product
examples often symlink the matching skill into `.agents/skills` so the catalog name resolves as well.

If PDS is a dependency but those files are missing, the agent should say so and fall back to generic HTML rules. Do not
treat `https://designsystem.porsche.com/v4/` as the installed version. If there is no PDS dependency, generate native
HTML and do not invent `p-*` tags.

## Installed files

See package docs in
[web-accessibility-codegen README](https://github.com/porsche-design-system/skills/tree/main/packages/web-accessibility-codegen).

After install, APM typically updates:

| Category                          | What gets installed or updated                                                         |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| **Manifest/lock**                 | `apm.yml`, `apm.lock.yaml`                                                             |
| **APM cache**                     | `apm_modules/`                                                                         |
| **Copilot/Claude/Cursor targets** | Instruction and `accessible-frontend` skill for available targets                      |

`apm install` deploys:

| Primitive   | Copilot                                                | Cursor                                 | Claude                                 |
| ----------- | ------------------------------------------------------ | -------------------------------------- | -------------------------------------- |
| Instruction | `.github/instructions/frontend-a11y.instructions.md`   | `.cursor/rules/frontend-a11y.mdc`      | `.claude/rules/frontend-a11y.md`       |
| Skill       | `.agents/skills/accessible-frontend/`                  | `.agents/skills/accessible-frontend/`  | `.claude/skills/accessible-frontend/`  |

For Codex/Gemini (root `AGENTS.md` / `GEMINI.md`), run `apm compile` after install. Do not paste a stub `AGENTS.md` over
an existing project file.

## Update and uninstall

**Update installed dependencies:**

```bash
apm update
```

Or bump the package ref in `apm.yml` and run:

```bash
apm install
```

**Uninstall the package:**

```bash
apm uninstall porsche-design-system/skills/packages/web-accessibility-codegen
apm prune
```

If your repo manages dependencies in `apm.yml`, remove the dependency entry there and run `apm install`.

## Limitations

Generation-time context does not certify accessibility and does not replace an audit. After the UI exists, run a guided
**WCAG 2.2 AA** audit via the `a11y-audit` prompt. See the
[**AI Accessibility Audit**](/must-know/accessibility/ai-accessibility-audit/) guide.

Component do/don'ts and the `aria` prop live in the installed PDS package skill, not in `web-accessibility-codegen`.

**Standard:** [WCAG 2.2 Level AA](https://w3.org/WAI/standards-guidelines/wcag). Porsche guidance:
[Accessibility of digital products at Porsche](https://ux.porsche.com/d/6VNB3CeLHcJz/accessibility#/accessibility/introduction).
