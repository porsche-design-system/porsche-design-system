## How it works

The new color system leverages the native CSS
[`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/light-dark) function. By
adopting this browser-native engine, we have eliminated proprietary switching logic in favor of a performant,
standardized architecture that responds instantly to user preferences.

### The Foundation: `color-scheme`

All system colors are controlled via the CSS
[`color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme) property and are
included in our mandatory [Global Styles](/stylesheets/introduction). These styles also provide utility classes for
selecting the active theme and a polyfill to ensure compatibility with browsers that do not yet support `light-dark()`
(see [browser support](https://caniuse.com/mdn-css_types_color_light-dark)).

By default, the Global Styles set `color-scheme: only light` on `:root`. Your application uses the **Light** theme and
is protected from being recolored by the browser (see [Browser Automatic Dark Mode](#browser-automatic-dark-mode)).

Apply these classes to the `html` element or any container to define the theme context:

- `.scheme-light-dark` — Automatically toggles based on **System/OS settings**. This is the recommended way to support
  dark mode.
- `.scheme-only-light` — Forces the **Light** theme and prevents the browser from recoloring it.
- `.scheme-only-dark` — Forces the **Dark** theme and prevents the browser from recoloring it.
- `.scheme-light` — Uses the **Light** theme, but still allows the browser to recolor it. Prefer `.scheme-only-light`.
- `.scheme-dark` — Uses the **Dark** theme.

## Browser Automatic Dark Mode

Some Chromium-based browsers and WebViews can darken websites automatically, e.g. Chrome on Android with "Auto Dark Mode
for Web Contents", Samsung Internet in dark mode or Android WebViews with algorithmic darkening. This only affects pages
that don't declare dark mode support. The browser then recolors backgrounds and text algorithmically, but images such as
the icons of PDS components are **not** reliably recolored. Dark icons can end up on a dark background and become
practically invisible, which is a functional and an accessibility issue.

The CSS keyword `only` opts out of this behavior. This is why the Global Styles use `color-scheme: only light` as
default. Safari doesn't support automatic dark mode, so it is not affected.

| Color scheme                         | Rendering in a browser with automatic dark mode |
| ------------------------------------ | ----------------------------------------------- |
| Default (`color-scheme: only light`) | ✅ PDS Light theme                              |
| `.scheme-only-light`                 | ✅ PDS Light theme                              |
| `.scheme-light-dark`                 | ✅ PDS Light or Dark theme, based on the OS     |
| `.scheme-only-dark`, `.scheme-dark`  | ✅ PDS Dark theme                               |
| `.scheme-light`                      | ❌ Recolored by the browser                     |

<Notification heading="Important" headingTag="h3" state="warning">
  To force the light theme, use `.scheme-only-light` instead of `.scheme-light` or `color-scheme: light`. Without
  `only`, the browser recolors the page or section. The same applies to custom styles, e.g. when overriding the
  `color-scheme` of a component: use `color-scheme: only light` instead of `color-scheme: light`.
</Notification>

Note that a `<meta name="color-scheme">` tag has no effect, because the `color-scheme` set by the Global Styles on
`:root` takes precedence. Use the `.scheme-*` classes instead.

## Scoping Themes

Theme context is hierarchical. You can nest these utility classes to create "islands" of different themes within your
application. This is particularly useful for dark-themed footers or light-themed modals on dark pages.

```js
<html class="scheme-light-dark">
  <body>
    <p-button>I follow the OS theme</p-button>

    <div class="scheme-dark">
      <p-heading>Dark Section</p-heading>
      <p-button>I use the Dark theme</p-button>
    </div>
  </body>
</html>
```

### Ecosystem Integration

The `color-scheme` utility classes do more than just update PDS components—they act as a global "source of truth" for
your entire styling stack. When you apply a `.scheme-*` class, it automatically synchronizes the theme across all our
supported styling tools:

- **[Tailwind CSS](/tailwindcss/introduction)**: Custom PDS color utilities (e.g., `text-primary`) automatically resolve
  to the correct light or dark values.
- **[SCSS](/scss/introduction)**: The PDS mixins and variables hook into the theme context, ensuring your custom
  stylesheets remain brand-compliant.
- **[Emotion](/emotion/introduction)**: Design tokens consumed via Emotion are reactive to the `color-scheme` defined on
  the parent container.
- **[Vanilla Extract](/vanilla-extract/introduction)**: Design tokens consumed via Vanilla Extract are reactive to the
  `color-scheme` defined on the parent container.

**Key Takeaway:** By using these utility classes, you ensure that your custom UI and PDS components always share the
same color palette and contrast ratios, regardless of the styling technology used.

## Fixed Light and Dark Sections

Use `.scheme-only-light` or `.scheme-only-dark` on a page section that must remain light or dark independently of its
parent scheme. This is useful for fixed campaign sections or other page islands within a page that otherwise follows the
user's system preference.

❌ Anti-pattern — overriding global PDS color variables:

```css
.campaign-section {
  --p-color-canvas: #0e0e12;
  --p-color-primary: #fff;
}
```

✅ Recommended — applying fixed schemes to page islands while continuing to consume PDS variables:

```html
<html class="scheme-light-dark">
  <body>
    <main>
      <section class="campaign-section scheme-only-dark">Dark campaign content</section>
      <section class="campaign-section scheme-only-light">Light campaign content</section>
    </main>
  </body>
</html>
```

```css
.campaign-section {
  background-color: var(--p-color-canvas);
  color: var(--p-color-primary);
}
```

## WebViews

Native apps that render web content in a WebView should pass the app theme on to the web content. Otherwise, the web
content may not match the app theme, or (on Android) the WebView may darken the web content automatically, depending on
the app theme.

- If the app supports light and dark mode, and the WebView reflects the app theme in `prefers-color-scheme`, use
  `.scheme-light-dark`.
- Otherwise, set `.scheme-only-light` or `.scheme-only-dark` on the `html` element of the web content, based on the
  active app theme.
