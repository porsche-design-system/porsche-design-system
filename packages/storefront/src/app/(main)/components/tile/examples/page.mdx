# Tile <ComponentStatus tagName="p-tile"></ComponentStatus>

The examples are structured by use case. The Tile has no built-in hover effect, so each clickable use case shows how to
tailor it to its content with a few custom styles. Since the slotted `anchor` covers the whole Tile and all other
content is click-through, hovering the anchor equals hovering the Tile, while independent interactive elements (which
opt in via `pointer-events: auto`) don't trigger it. Wrap transitions in `motion-safe:` to respect the user's preference
for reduced motion. Hover effects are a visual enhancement only, keyboard users get the focus indicator of the anchor.
Use cases with multiple independent actions or none at all don't use the `anchor` slot.

For comparison, each example shows the Tile next to or, for wide tiles, above a counterpart built with Tailwind CSS
only. Instead of the `anchor` slot, it stretches a link over the whole tile via
`after:absolute after:inset-0 after:z-1`, which also renders the focus indicator around the tile, and places independent
interactive elements above it via `relative z-2`. Since the link belongs to the visible text, it gets its accessible
name from it.

## Slot-based Layouts

These use cases are built with the slots of the Tile: the content is placed in the `top`, `start`, default, `end` and
`bottom` slots, the `background` slot holds a mood image and properties like `aspect-ratio`, `compact` and `gradient`
adapt the Tile to its content. Custom styles are limited to the content itself, e.g. spacing, hover effects or an image
bleeding to the edges of the Tile.

## Custom Layouts (Pattern Candidates)

These use cases bypass the layout of the Tile: they stretch the default slot to define their own grid, or remove the
padding, background and corner radius of the Tile, so it only provides the clickable area and its focus indicator. Since
most of the layout is custom code, they are candidates for a pattern rather than use cases of the Tile.
