## Accessibility support

### Keyboard

| Key / state        | Function                                                                           |
| ------------------ | ---------------------------------------------------------------------------------- |
| `Tab`, `Shift-Tab` | Moves focus to the next (or previous) focusable element.                           |
| `Enter/Space`      | When focus is on the accordion trigger, the associated panel expands or collapses. |

## Development considerations

### Heading hierarchy

The accordion summary should be a heading element (e.g.,`p-heading` or `<h1>` to `<h6>`,) to ensure proper semantic
structure and correct heading hierarchy.

### Common do's and don'ts

- **Do** use the `summary` slot with a heading element such as `p-heading` or native `h1`–`h6`.
- **Do** keep heading levels sequential across multiple accordions on a page.
- **Don't** use plain text in the summary without a semantic heading.

## Integration examples

### Accordion summary without semantic heading

❌ Anti-pattern

```js
<p-accordion>
  <span slot="summary">Delivery options</span>
  <p-text>Content about delivery.</p-text>
</p-accordion>
```

✅ Recommended

```js
<p-accordion>
  <p-heading slot="summary" tag="h2" size="sm">
    Delivery options
  </p-heading>
  <p-text>Content about delivery.</p-text>
</p-accordion>
```

### Skipped heading level

❌ Anti-pattern

```js
<p-heading tag="h1">Configure your Porsche</p-heading>
<p-accordion>
  <p-heading slot="summary" tag="h4" size="sm">Delivery options</p-heading>
  ...
</p-accordion>
```

✅ Recommended

```js
<p-heading tag="h1">Configure your Porsche</p-heading>
<p-accordion>
  <p-heading slot="summary" tag="h2" size="sm">Delivery options</p-heading>
  ...
</p-accordion>
```
