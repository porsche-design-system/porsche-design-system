## Accessibility support

### ARIA enhancements

#### External **ARIA** provided by the `aria` property:

| ARIA         | Usage                                               |
| ------------ | --------------------------------------------------- |
| `aria-label` | Defines a string value that labels the live region. |

#### Internal **ARIA** that is managed by the component:

| ARIA           | Usage                          |
| -------------- | ------------------------------ |
| `role="alert"` | Provided message is announced. |

## Development considerations

### Announcing loading messages

To provide feedback to screen reader users, it is mandatory to announce the loading state of the spinner. This can be
achieved in the following ways:

- Pre-rendering the component in the DOM.
- Providing a meaningful loading state message through the `aria` property, e.g.
  `aria="{ 'aria-label': 'Start/End loading content'}"`.

### Common do's and don'ts

- **Do** pre-render the spinner when loading feedback must be announced.
- **Do** provide a specific loading message through the `aria` prop.
- **Don't** mount the spinner only at the moment loading starts without a label.

## Integration examples

### Spinner mounted only when loading starts

❌ Anti-pattern

```js
if (isLoading) {
  container.innerHTML = '<p-spinner></p-spinner>';
}
```

✅ Recommended

```js
<p-spinner aria="{ 'aria-label': 'Loading vehicle configuration' }"></p-spinner>
```

### Spinner without loading message

❌ Anti-pattern

```js
<p-spinner></p-spinner>
```

✅ Recommended

```js
<p-spinner aria="{ 'aria-label': 'Loading vehicle configuration' }"></p-spinner>
```
