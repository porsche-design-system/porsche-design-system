## 2. Link the Skill

Since AI integrations discover skills in dedicated directories rather than `node_modules`, the bundled skill has to be
linked into the skills directory your AI coding tool reads. Pick one of the methods below.

<ContentTabs label="Installation method">

<ContentTab label="Bundled binary">

Each supported Porsche Design System npm package includes the `pds-skill` binary, which creates the project-local
symlink for you. Run it from the project or workspace where the package is installed:

<FrameworkCodeBlock
  language="bash"
  render={({ componentPackageName }) =>
    `npx pds-skill --package ${componentPackageName} --location {.agents|.claude|.github}/skills`
  }
/>

- `--package` selects the Porsche Design System npm package installed in your project.
- `--location` sets the integration's parent skills directory. The binary creates the skill folders inside it.
- `--skill` optionally installs only the named skill and can be repeated. Omit it to install all bundled skills.

On macOS and Linux the created symlinks point at the package with a relative target, so they stay valid across
symlink-capable clones and in CI. Commit them and teammates whose Git checkout supports symlinks get the skills right
after `npm install`. On Windows the binary creates a directory junction instead, because a directory symlink requires
elevated privileges or Developer Mode there. A junction always stores an absolute path, so it is machine-specific and
should not be committed.

For `--location`, use the directory your AI coding tool reads: `.agents/skills` is the Agent Skills standard and is also
picked up by Codex and GitHub Copilot, `.claude/skills` is used by Claude Code, and `.github/skills` by GitHub Copilot.
If your team uses several agents, link the skill into each of the directories they read.

<FrameworkCodeBlock
  language="bash"
  render={({ componentPackageName }) => `
    npx pds-skill --package ${componentPackageName} --location .agents/skills # Agent Skills standard, Codex, GitHub Copilot
    npx pds-skill --package ${componentPackageName} --location .claude/skills # Claude Code
    npx pds-skill --package ${componentPackageName} --location .github/skills # GitHub Copilot
  `}
/>

To link a single skill only, pass its directory name:

<FrameworkCodeBlock
  language="bash"
  render={({ componentPackageName, getSkillName }) =>
    `npx pds-skill --package ${componentPackageName} --location .agents/skills --skill ${getSkillName('knowledge')}`
  }
/>

</ContentTab>

<ContentTab label="Manual symlink">

Create the project-local link yourself, inside the directory your AI coding tool reads: `.agents/skills` is the Agent
Skills standard and is also picked up by Codex and GitHub Copilot, `.claude/skills` is used by Claude Code, and
`.github/skills` by GitHub Copilot.

On macOS or Linux, run this from the repository root. The link target is relative to the skills directory, which keeps
the link portable across clones and CI:

<FrameworkCodeBlock
  language="bash"
  render={({ componentPackageName, getSkillName }) => `
    mkdir -p .agents/skills
    ln -s ../../node_modules/${componentPackageName}/skills/${getSkillName('knowledge')} \\
      .agents/skills/${getSkillName('knowledge')}
  `}
/>

The `../../` prefix goes up from `.agents/skills` to the repository root. Adjust it if you link into a directory at a
different depth.

On Windows, create a directory junction from the repository root instead:

<FrameworkCodeBlock
  language="text"
  render={({ componentPackageWindowsPath, getSkillName }) =>
    `mklink /J .agents\\skills\\${getSkillName('knowledge')} node_modules\\${componentPackageWindowsPath}\\skills\\${getSkillName('knowledge')}`
  }
/>

Create one link per skill you want to use and per skills directory your team's agents read. Commit the relative links so
teammates with symlink-capable Git checkouts get them right after `npm install`. A Windows junction always stores an
absolute path, so it is machine-specific and should not be committed. A Windows clone without Git symlink support checks
a committed link out as a plain text file; delete it and re-run the binary to create a junction.

</ContentTab>

<ContentTab label="AI integration setting">

Some AI integrations and editors let you configure additional locations where skills are looked up. If yours does, you
can point it directly at the `skills` directory inside the installed Porsche Design System package, which makes a
symlink unnecessary.

For example, GitHub Copilot in VS Code offers this through `.vscode/settings.json`:

<FrameworkCodeBlock
  language="json"
  render={({ componentPackageName }) => `
    {
      "chat.agentSkillsLocations": ["./node_modules/${componentPackageName}/skills"]
    }
  `}
/>

Support for such a setting differs per integration and changes quickly, so check the documentation of the AI integration
or editor you use for an equivalent option. If none exists, use one of the symlink-based methods instead. Also keep in
mind that these settings are usually specific to a single integration, so a project used with several agents may still
need a skills directory entry.

</ContentTab>

</ContentTabs>

## 3. Verify the Skill

Reload your AI coding agent or start a new agent session, then confirm that <code><FrameworkSkill /></code> is
available:

- **Claude Code:** Type `/` and look for the skill.
- **GitHub Copilot CLI:** Run `/skills reload`, then `/skills list`.
- **GitHub Copilot in VS Code:** Type `/skills` in the chat input to open the Configure Skills menu.
- **Codex:** Run `/skills` or type `$` and look for the skill.

## Updating

Skills are versioned together with the Porsche Design System package that contains them. Updating the package to a newer
version also updates the linked skills, so no additional step is needed as long as the symlink or configured location
keeps pointing at the installed package.

Re-run the installation only if you remove the link, switch to a different Porsche Design System package or want to add
a skill that was not linked before. Re-running is safe: an existing link that already points at the installed package is
left untouched, and a link created by a version of `pds-skill` that still wrote absolute targets is converted to a
relative one.
