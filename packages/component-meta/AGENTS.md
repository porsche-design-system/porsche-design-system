# AGENTS.md — Component Meta Package

> This file provides context for AI coding assistants working in `packages/component-meta/`.

## Overview

This package generates and bundles structured metadata for PDS components. It inspects component source files, extracts documented props/events/slots/css variables, and publishes the resulting metadata helpers.

## Structure

```text
packages/component-meta/
├── scripts/               # Metadata generation scripts
├── src/index.ts           # Public entrypoint
├── src/lib/               # Generated metadata output
├── src/types/             # Metadata type definitions
├── src/utils/             # Generation helpers
└── tests/                 # Unit tests
```

## Commands

```bash
# Build generated metadata and bundle package
npm run build:component-meta

# Run unit tests
npm run test:unit:component-meta
```

## Generated Files

- `src/lib/componentMeta.ts` is generated by `scripts/generateComponentMeta.ts`.
- Do not hand-edit generated files in `src/lib/` or `dist/`.
- If you change extraction logic, types, or source parsing, rebuild the package and verify the generated output.

## Implementation Notes

- The generator reads component source from `../components/src/components`.
- Extraction is based on source analysis and documented patterns such as `@slot`, `@css-variable`, and `@controlled`.
- Preserve existing docblock and source conventions unless the task explicitly updates the metadata format.
- Be careful with regex- and `eval`-based parsing in generation scripts; small syntax changes in component source can have broad downstream effects.

## Testing Expectations

- Add or update unit tests when metadata shape or extraction logic changes.
- Prefer targeted changes to generation logic over broad rewrites.
- If a change affects produced metadata, verify both script output and consumer-facing types.
