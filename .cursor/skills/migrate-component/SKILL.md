# Migrate Component

When refactoring or renaming a component, ensure all related files across the monorepo are updated consistently.

**Component name**: read from the user's message (the current kebab-case name, e.g., `button`). Ask the user if not provided.

## Steps

### 1. Inventory all related files

Search the entire monorepo for files related to the component. Check each of these locations:

**Component source** (`packages/components/`):
- `src/components/{name}/` — all component files (.tsx, -styles.ts, -utils.ts, .spec.ts, .props.md)
- `src/components/*/` — other components that may import from this component's utils
- `src/utils/` — utility files that reference this component

**Test harness** (`packages/components-js/`):
- `tests/e2e/specs/{name}.e2e.ts`
- `tests/vrt/specs/{name}.vrt.ts`
- `tests/a11y/specs/axe-core/{name}.a11y.ts`
- `tests/a11y/specs/a11ytree/{name}.a11y.ts`
- `src/pages/` — test pages that render this component

**Storefront** (`packages/storefront/`):
- `src/app/components/{name}/` — documentation pages and stories
- Other MDX files that reference `p-{name}`

**Shared** (`packages/shared/`):
- `scripts/generateCodeExamples.ts` — code example registration
- `src/data/` — any data referencing this component
- `src/lib/` — generated tag name lookups (will regenerate)

**Component Meta** (`packages/component-meta/`):
- Generated metadata (will regenerate on build, but verify)

**Wrapper generators** (`packages/components/scripts/wrapper-generator/`):
- Check if component has special handling in any generator

### 2. Report the inventory

Present the full list of files found, organized by package. Highlight:
- Files that need manual updating
- Files that will auto-regenerate on build
- Files where references exist but may not need changes

### 3. Execute the migration

For each file that needs updating:
- Make the necessary changes
- Preserve existing test coverage
- Maintain accessibility compliance

### 4. Rebuild and verify

After all changes:

```bash
npm run build:shared
npm run build:component-meta
npm run build:components
npm run build:components-js
npm run build:components-react && npm run build:components-angular && npm run build:components-vue
npm run test:unit:components -- {name}
```

Report any remaining issues.

### 5. Generate checklist

Output a summary of everything changed and what still needs manual verification (e.g., VRT snapshot updates, storefront preview).

## In this repository (Porsche Design System)

- Build order matters: shared → component-meta → components → components-js → wrappers
- VRT snapshots will need updating after renames: `./docker.sh npm run test:vrt:components-js`
- Generated wrapper files in components-react/angular/vue are regenerated by the build — do not hand-edit them
